# Security Policy

## Reporting a Security Vulnerability

The security of TestZombie is important to us.

If you discover a potential security vulnerability in TestZombie, please **do not open a public GitHub issue** and do not disclose the vulnerability publicly before we have had a reasonable opportunity to investigate and address it.

Please report security vulnerabilities privately by email:

**security@testzombie.ai**

Additional information is available at:

**https://testzombie.ai/security**

## What to Include

To help us investigate your report efficiently, please include as much of the following information as possible:

- affected TestZombie product or component
- affected version, if known
- description of the vulnerability
- steps to reproduce
- proof of concept, logs, screenshots, or relevant technical details
- potential security impact
- whether you are aware of active exploitation
- suggested mitigation or remediation, if available
- your preferred contact information

Please do not include unnecessary customer data, credentials, API keys, secrets, or other sensitive information in the report.

## Our Response

We will review security reports as quickly as reasonably possible and may contact you for additional information.

Confirmed vulnerabilities are assessed based on their severity, exploitability, affected components, and potential impact. Where appropriate, we will prepare a remediation, mitigation, or security update.

We may coordinate the timing of disclosure with the reporter to reduce risk to TestZombie users.

## Coordinated Disclosure

We ask security researchers and reporters to:

- give us a reasonable opportunity to investigate and remediate the issue before public disclosure
- avoid accessing, modifying, deleting, or downloading data that does not belong to them
- avoid actions that could disrupt TestZombie services or customer environments
- use only the minimum access necessary to demonstrate the vulnerability
- keep vulnerability details confidential while remediation is in progress

If you accidentally access customer or personal data while investigating a vulnerability, please stop further access and notify us immediately.

## Supported Versions

Security fixes are generally provided for supported TestZombie versions.

The exact affected and fixed versions will be communicated in the relevant security advisory or release information where necessary.

Users are encouraged to keep TestZombie dependencies and client components up to date.

## Security Updates

Security-relevant dependency and vulnerability findings are reviewed as part of the TestZombie release process.

Where a security update is required, we aim to provide an updated version or appropriate mitigation and communicate relevant information to affected users.

## Scope

This policy applies to security vulnerabilities affecting TestZombie software and services, including where applicable:

- TestZombie Java / Selenium components
- TestZombie Appium / mobile components
- TestZombie client and driver components
- TestZombie APIs and backend services required for product operation

For general support questions, feature requests, or non-security bugs, please use the normal TestZombie support channels or GitHub issue tracker.

## Responsible Disclosure and Legal Compliance

TestZombie follows a coordinated vulnerability disclosure process and maintains internal procedures for handling security vulnerabilities and incidents, including applicable regulatory reporting obligations.

Please report vulnerabilities responsibly and in accordance with applicable law.
